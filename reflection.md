From the readings, one thing I learned was how to use Issues. Issues are used to track things that need to be fixed, added, or changed. You can either create a new draft issue or type an issue number to add to an existing issue. When you create a new issue, you should make sure to describe the task so you can keep track of it throughout the project and have proper documentation. Draft issues can be easily converted to Issues, and Issues can be linked to pull requests and closed when the work is complete.

One challenge I faced so far in GitHub was accidentally writing an explanation of a commit in the wrong spot. I put the explanation in the description section rather than the summary section of the commit. Although this isn't necessarily wrong, it is different from the example we learned in class. From now on, I have made sure to write the commit message in the correct spot. 

GitHub will help in my future projects by enabling collaboration. By allowing team members to work on the project at the same time, time can be saved. This occurs by creating multiple branches and having team members work on individual ones. It also opens the floor for discussion between team members and actually encourages it. This is because before anything is merged into the main branch, a pull request is created so that any edits can be reviewed by another member of the team. This is super helpful because a teammate might see an error in your work that you don't. Overall, GitHub can help make team projects be more accurate and efficient.
